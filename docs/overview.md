## 0. 一句话概括

用 **STM32F103C8T6 + 8 个 SG90 舵机**做一只 8 自由度四足（机器狗）机器人，**纯开环 8 相位步态**走完 900 mm 直道，靠 **HC-05 蓝牙单步微调**做终点精准停靠，电源用 **2S 锂电 + XL4015 降压 + 2×1000 µF**，控制板为自制 **50×80 mm 双层 PCB**（Gerber 已出），机身是 **3D 打印件（75×66×10 mm）**。

**当前状态**：站立稳定；直行能走直线（最好记录 57 cm）；已加入原地左/右转；`TARGET_STEPS` 仍未标定；OLED 用 **PB12/PB13** 已点亮并能显示表情；代码工程见 `D:\下载\robot2-main`（Keil MDK，已含全部 HAL 驱动）。

### 1.2 本队的得分打法（已确定，不再改）

1. **基础分优先**：宁可慢，必须走完 900 mm 且不出界（出界立即停止，按出界点计分）。
2. **附加分靠"人机协同"**：不做视觉/循迹，用手机蓝牙发单步指令，肉眼对准终点线一点点挪——这是低成本方案里最稳的精准停靠。
3. **创新分靠硬件**：自制 PCB + 模块化舵机接口 + 双模控制（蓝牙 + 物理按键应急）。
4. **答辩分靠设计叙事**：8 相位错峰、非阻塞调度、电源抗扰——三个点足够讲。

| 环节 | 预算 |

| 上电自检 + 站立 | 2 s |

## 3. 电源与 PCB

### 3.1 电源架构（**这是本项目最大的坑**）

```
电池 XT60 → 船型/拨动开关 → 2×1000µF 并联 →┬→ XL4015 → 5V → VCC_SERVO（8 舵机，粗线 60mil）
                                            └→ 5V → VCC（MCU/蓝牙/OLED/蜂鸣器，20mil）
```

**原则：舵机的大电流路径要尽可能独立；MCU 只从电源汇合点分一条细支路取电，别和 8 个舵机共用同一条粗干路。**

- 原因：8 个 SG90 同时启动峰值 **5 A 以上**，共用一条细线会把 5 V 拉到 MCU 欠压复位（Brown-out）。
- 本项目的实际做法：**没有割焊盘，而是把引到 MCU 5V 的那段电源线线宽改小**——主控支路只分小电流，舵机侧仍走 60 mil 粗干路，形成"粗干路 + 细支路"的结构。
- ⚠️ 代价：细线本身有压降，所以必须配 2×1000 µF 蓄水电容 + 软件 8 相位错峰，否则启动/急停瞬间仍可能复位。
- 如果还能改板：把 `VCC`/`VCC_SERVO` 做成两个独立网络，在电容正极单点汇合，各自再加 100 nF 去耦。

### 3.2 线宽标准（50×80 mm，1 oz 铜）

| 档次 | 线宽 | 用途 |
| --- | --- | --- |
| 大电流 | **≥ 60 mil** | 电池输入、开关、电容正极、舵机 VCC 主干 |
| 主控 | 20 mil | 5V 主控干路、GND 主干 |
| 信号 | 10~15 mil | PWM、I2C、UART、按键 |

### 3.3 PCB 设计要点（已验证）

- 布局：电源居中/靠边、**舵机接口就近贴着 PWM 输出引脚放（PA0~PA3 / PA6、PA7、PB0、PB1）**、核心板居中竖放——舵机线不用横穿整板，线束好理，也呼应"禁止飞线/杜邦线"的要求。
- 地：**底层整片 GND 铺铜**，顶层可不铺。
- 固定：板上打的那几个孔**是为了用螺丝把板子固定在 3D 打印机身上**（不是电气缝合孔），做**非金属化（NPTH）**，防止螺丝短接底层地。
- 蓝牙：模块天线**正下方禁布铜**（设 Keep-Out）；若用杜邦线外接则无需处理。
- 舵机接口：4 个 2×3 排针（H1~H4），每口引出 `VCC_SERVO / GND / PWM`；建议改 **JST-XH** 防脱落。
- 禁止：TP4056 充电电路、XM 供电切换电路、把 3.3V 接到 5V（会烧核心板）。

## 4. 软件架构

### 4.1 CubeMX 配置清单（照抄即可）

**时钟**：HSE 8 MHz 晶振 → PLL ×9 → **SYSCLK 72 MHz**；AHB 72 M，APB1 36 M，APB2 72 M。

**TIM2 / TIM3（各 4 通道 PWM）**

| 参数 | 值 | 说明 |
| --- | --- | --- |
| Prescaler | **71** | 72 MHz / 72 = 1 MHz，即 1 µs 计数 |
| Counter Period (ARR) | **19999** | 20 ms 周期 = 50 Hz |
| Pulse | 1500 | 初始 90° 中位 |
| Mode | PWM Mode 1 / High | |

**USART1**：9600、8N1、无流控、PA9/PA10，**开启全局中断**（优先级 1）。

**GPIO**：见 2.3 表。OLED 两脚必须 **Output Open-Drain + Pull-up**（软件 I2C 总线要求，推挽会烧屏）。

**中断**：只开 USART1（蓝牙）+ SysTick。按键/红外若要中断，走 EXTI9_5。

├── robot.ioc                    CubeMX 工程文件
├── Core/
│   ├── Inc/   main.h  tim.h  usart.h  gpio.h  stm32f1xx_it.h  hal_conf

- 步态、姿态、调度全部在 `Core/Src/main.c`（`SetServo` / `Robot_Stand` / `Robot_Walk_Forward_Step` / `Robot_Turn_*_Step` / `Robot_Gait_Run` / `BT_Process` / `OLED_ShowFace`）。
- `HARDWARE\` 需在 Keil 的 `Options → C/C++ → Include Paths` 中加入，否则 `OLED.h` 等找不到。
- 同目录 `robot_main.c` 与本仓 `Core/Src/main.c` **完全一致**（已比对哈希），可直接对照。

### 4.3 三层架构（答辩就用这个说法）

```
第一层  宏观任务状态机   currentMotion: MOTION_STOP / FORWARD / TURN_LEFT / TURN_RIGHT
第二层  微观步态相位机   stepPhase: 0~7，每次只执行一个相位（错峰）
第三层  非阻塞调度       HAL_GetTick() 时间片，不用 HAL_Delay 卡死主循环
```

> 注意：`TURN_LEFT / TURN_RIGHT` 一旦进入会**一直原地转**，只有发 `'0'` 才停——比赛用不上就别按，或改成"转 N 步自动回 STOP"。

### 4.4 8 相位步态（对角步态 Trot 的简化版）

| 相位 | 动作 | 目的 |
| --- | --- | --- |
| 0 | 回到准备姿态 | 每步重新对齐基准 |
| 1 | 抬左前膝(2)、右后膝(8) | 对角支撑 |
| 2 | 左前髋(1)、右后髋(7) 迈步 | 产生推力 |
| 3 | 左前膝、右后膝落地 | |
| 4 | 抬右前膝(4)、左后膝(6) | 换对角 |
| 5 | 右前髋(3)、左后髋(5) 迈步 | |
| 6 | 右前膝、左后膝落地 | |
| 7 | 四髋回正一半 | 重心过渡，防侧翻 |

**为什么拆 8 个相位而不是一次全动**：① 峰值电流从 5 A 压到 ~1.5 A；② 机械不打架；③ 重心转移平滑不侧翻。这一点是答辩的必答项。

### 4.5 蓝牙协议（极简单字符）

| 指令 | 动作 | 用途 |
| --- | --- | --- |
| `'1'` | 进入 `MOTION_FORWARD`，`motionSteps=0` | 开跑 |
| `'0'` | 立即 `MOTION_STOP` + `Robot_Stand()` | 急停（保命） |
| `'2'` | `micro_step_request=1`，走完整 1 步 | 终点微调 |
| `'3'` | 进入 `MOTION_TURN_LEFT` | 原地左转（持续） |
| `'4'` | 进入 `MOTION_TURN_RIGHT` | 原地右转（持续） |

接收方式：USART1 RXNE 中断里只做"收字节 + 置标志"，**绝不在中断里跑步态**，主循环 `BT_Process()` 解析。这样急停延迟 < 10 ms。

## 5. 关键参数与标定

### 5.1 舵机角度映射

```c
pulse = angle / 180.0f * 2000.0f + 500.0f + 0.5f;   // 0°→500, 180°→2500
```
1 MHz 计数下，500~2500 对应 SG90 的 0.5~2.5 ms。`+0.5f` 是四舍五入，减 ±0.5° 的量化误差。

### 5.2 黄金站姿（实测能站稳，别乱改）

| 舵机 | 1 左前髋 | 2 左前膝 | 3 右前髋 | 4 右前膝 | 5 左后髋 | 6 左后膝 | 7 右后髋 | 8 右后膝 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 角度 | 90 | **76** | 90 | **95** | 90 | **80** | 90 | **100** |

四髋全 90° 保证指向前后；四个膝角各不相同，是**打印件公差 + 舵机齿位误差**的补偿，不是笔误。
> 换新舵机/重新装配后必须重新调这 4 个值：先让机器人四脚均匀着地，再微调膝盖直到不晃、不翘脚。

### 5.3 步态参数（`main.c` 顶部宏）

| 宏 | 现值 | 含义 | 怎么调 |
| --- | --- | --- | --- |
| `SIDE_ANGLE` | **20** | 大腿前后摆幅（°） | 越大步幅越大；>30 容易侧翻 |
| `TURN_ANGLE` | **25** | 原地转向时髋关节偏移（°） | 越大转得越快，>30 易扭 |
| `STEP_DELAY` | **100 ms** | 单个相位时长 | 8 相位 = **800 ms/步**；改小提速但易打滑 |
| `TARGET_STEPS` | **60** | 走完 900 mm 的步数 | **必须实测标定，见下** |

> 按当前参数：一步 0.8 s，60 步 = **48 s**，加急停/微调仍在 90 s 内，但偏慢。若标定后步数 < 45，可把 `STEP_DELAY` 降到 70~80 ms 换速度。

### 5.4 距离标定流程（做一次，10 分钟）

1. 地面贴 1 m 胶带尺，起点对齐机器人**机身中心**。
2. 临时把 `TARGET_STEPS` 改成 20，蓝牙发 `'1'` 跑完，量实际位移 `D`（mm）。
3. 单步位移 `d = D / 20`。
4. `TARGET_STEPS = round(900 / d)`，再留 1~2 步余量（宁少勿多，越界即 0 分）。
5. 复测一次 900 mm，偏差 > 30 mm 就重标。

> 历史数据只能参考、不能直接抄：曾测到 10 步走 200 mm（d=20 mm，900 mm≈45 步），也出现过 95 步只走 200 mm（d≈2 mm，说明当时步态在"原地蹭"）。**换一次代码/换一次地面，d 就会变。**

### 5.5 调参顺序（别跳步）

```
站立稳定 → 单步能迈出（不打滑） → 走 3 步不偏 → 走 10 步标定 d → 算 TARGET_STEPS
        → 走 900 mm 看偏航 → 微调左右差速 → 终点蓝牙微调
```

## 6. 踩坑清单（最值钱的部分）

| # | 现象 | 根因 | 结论 |
| --- | --- | --- | --- |
| 1 | 舵机只响不转 | 信号共地没接 / 供电不足 | 舵机电源与 MCU **必须共地**；不要用 MCU 的 5V 带舵机 |
| 2 | 上电 1 号舵机狂转 | PWM 未初始化就输出 / 角度越界 | 先 `HAL_TIM_PWM_Start` 再给角度；确认是 180° 舵机 |
| 3 | 8 舵机一起动就复位 | 浪涌电流拉低 5V | 主控支路走细线 + 2×1000 µF 蓄水 + 8 相位错峰 |

## 8. 答辩话术（精简版）

**Q：控制架构？**
主控 STM32F103 出 8 路 50 Hz PWM 跑 8 相位状态机；执行层是 8 个 SG90，内部电位器自带关节闭环；通信层 HC-05 收手机指令，OLED 实时回显状态；整体非阻塞调度，急停指令随时可打断。

**Q：没有 IMU，怎么保证走直？**
承认是"开环步态 + 人工微调"：底层靠舵机闭环，顶层靠赛前标定的对称步态 + 蓝牙单步补偿。并说明取舍："20 天周期里，稳定完赛优先于姿态闭环；若加 MPU6050，会对 Roll/Pitch 做串级 PID。"

**Q：为什么拆 8 个相位？**
一次全动峰值 5 A 会拉垮 5 V 导致 MCU 复位；拆分后每次最多 2 个舵机动作，峰值降到 1.5 A，同时重心转移平滑、机械不干涉。

**Q：电源怎么抗干扰？**
2S 锂电 → XL4015 → 5 V；两颗 1000 µF 作蓄水池；舵机 60 mil 粗干路 + 主控细支路；底层整片铺地。

**Q：这套代码的工程亮点？**
① `HAL_GetTick()` 非阻塞调度，不用死延时；② 8 相位 + `static` 相位记忆实现错峰；③ `micro_step_request` 标志位实现毫米级停靠；④ `SetServo(id,angle)` 把业务层与 TIM 通道解耦。

### 11.3 150 mm 尺寸校核（赛前必做）

规则是**静置状态**长宽高均 ≤ 150 mm。机身本体 75×66 没问题，风险在四条腿外伸：

| 方向 | 机身尺寸 | 允许外伸 | 判定方法 |
| --- | --- | --- | --- |
| 左右（宽） | 66 mm | **每侧 ≤ 42 mm** | 腿完全展开后量总宽 |
| 前后（长） | 75 mm | **每端 ≤ 37.5 mm** | 量总长 |
| 高度 | 10 mm（板） | 站立总高 ≤ 150 mm | 几乎不可能超 |

**结论：站立展开时若单侧外伸超过 37.5 mm 就超尺寸。** 处理办法：① 比赛检录时把腿收拢成"趴伏姿态"再量；② 或缩短脚掌外伸量。**现在没有实测数据，这一项必须用卡尺量一次并拍照留证。**
